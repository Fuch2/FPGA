## 3. Соединения

### 3.1. Плата A ↔ плата B (SPI), 5 проводов «мама-мама»

| Сигнал | Плата A (МО, мастер) | Провод | Плата B (МИ, слейв) |
|---|---|---|---|
| CS_N | вывод **1** | → | вывод **1** |
| MISO | вывод **2** | ← | вывод **2** |
| MOSI | вывод **3** | → | вывод **3** |
| SCK | вывод **7** | → | вывод **7** |
| GND | GND гребёнки | — | GND гребёнки |

- Уровни 3.3 В с обеих сторон, преобразователи не нужны.
- 5V и 3.3V между платами **не соединять**: каждая плата питается от своего USB/блока.
- Провода не длиннее 20–30 см.
- Сначала соединить GND, потом сигнальные провода. Платы прошиваются каждая своим USB-Blaster.

### 3.2. МУ ↔ плата A (UART)

| Адаптер YP-01 | Плата A |
|---|---|
| TXD | вывод 10 (`uart_rx`) |
| RXD | вывод 11 (`uart_tx`) |
| GND | GND |
| VCC | не подключать |

### 3.3. МИ ↔ ДТ и EEPROM

Обе микросхемы на плате B, на шине I2C (PIN_99/98), проводов не нужно.

| Микросхема | 7-битный адрес | Статус |
|---|---|---|
| LM75A | 0x48 (1001 A2 A1 A0, если A2..A0 = 0) | [не проверено], I2C-сканер на этапе 4 |
| AT24C08 | 0x50..0x53 (1010 A2 P1 P0: P1 P0 = блок 256 байт, если A2 = 0) | [не проверено], I2C-сканер на этапе 4 |

### 3.4. МО ↔ «Flash»

SDRAM на плате A, проводов не нужно.

## 4. Форматы данных

| Величина | Формат | Единицы |
|---|---|---|
| Температура (измеренная, фильтрованная) | int16 со знаком, дополнительный код, **Q8.8** | 1 LSB = 1/256 °C. Целая часть = `T >>> 8` |
| Ошибка = измеренное − отфильтрованное | int16 со знаком, Q8.8, с насыщением до −32768..32767 | 1/256 °C |
| Порядок байт во всех кадрах | старший байт первым (big-endian) | |

Значение с LM75A: регистр температуры 0x00, 2 байта, старший первым, 11 значащих бит D15..D5, шаг 0.125 °C. Это и есть Q8.8, младшие 5 бит = 0, поэтому слово от ДТ передаётся дальше **без преобразования**. Пример: 0x1960 = 25.375 °C, 0xFF00 = −1.0 °C. Свободные дробные биты пригодятся ЦФ.

## 5. UART МУ ↔ МО

115200 бит/с, 8N1, без управления потоком.

### 5.1. Команды МУ → МО (1 байт)

| Байт | Команда | Действие МО |
|---|---|---|
| `0x01` | Старт | сброс указателей Flash, «Старт» в МИ по SPI, запуск таймеров 1 и 2 |
| `0x02` | Стоп | остановка таймеров 1 и 2, «Стоп» в МИ по SPI |
| другие | — | игнорируются (счётчик мусора для индикации) |

Подтверждения команд нет: признак работы — приходящие пакеты.

### 5.2. Пакет данных МО → МУ (8 байт)

| Байт | Содержимое |
|---|---|
| 0 | `0xAA` — синхробайт |
| 1, 2 | измеренное значение (MEAS), Q8.8 |
| 3, 4 | отфильтрованное значение (FILT), Q8.8 |
| 5, 6 | ошибка (ERR = MEAS − FILT), Q8.8 |
| 7 | CHK = XOR байтов 1..6 |

МУ ищет `0xAA`, принимает 8 байт, проверяет CHK; при ошибке сдвигается на 1 байт и ищет следующий `0xAA` (байт `0xAA` может встретиться и в данных, CHK отсекает ложную синхронизацию).

## 6. SPI МО ↔ МИ

- Режим 0 (CPOL = 0, CPHA = 0): данные выставляются по спаду SCK, защёлкиваются по фронту. Старший бит первым.
- SCK = 1 МГц (50 МГц / 50). Слейв синхронизирует SCK, MOSI, CS_N в домен 50 МГц (2 триггера) — запас 25 тактов на полупериод.
- CS_N = 0 → первый фронт SCK: не менее 1 мкс. Между транзакциями CS_N = 1 не менее 2 мкс.
- **Транзакция всегда 4 байта** при CS_N = 0. Обмен полнодуплексный.

### 6.1. Кадр

| Байт | MOSI (МО → МИ) | MISO (МИ → МО) |
|---|---|---|
| 0 | CMD | STATUS |
| 1 | `0x00` | D_H — старший байт значения |
| 2 | `0x00` | D_L — младший байт значения |
| 3 | `0x00` | CHK = ~(STATUS ^ D_H ^ D_L) |

Инверсия в CHK нужна, чтобы и «залипший 0» (все байты 0x00), и обрыв MISO с подтяжкой (все 0xFF) давали ошибку контрольной суммы.

Слейв защёлкивает слово {STATUS, D_H, D_L, CHK} в момент спада CS_N и отдаёт его в этой транзакции. Команда в байте 0 исполняется после подъёма CS_N.

### 6.2. Команды МО → МИ

| CMD | Команда | Действие МИ |
|---|---|---|
| `0xA1` | Старт | сброс указателей EEPROM, запуск таймера МИ |
| `0xA2` | Измерение | чтение самого старого непрочитанного значения из EEPROM (FIFO), результат в D |
| `0xA3` | Стоп | остановка таймера МИ |
| `0x00` | NOP | ничего, используется для чтения ответа |
| другие | — | игнорируются |

### 6.3. STATUS

| Бит | Имя | Значение |
|---|---|---|
| 7 | MARK | всегда 1 |
| 6 | — | 0 |
| 5 | OVF | кольцо EEPROM переполнялось после «Старт» (потеряны старые значения) |
| 4 | I2C_ERR | последняя операция с ДТ или EEPROM закончилась NACK или тайм-аутом |
| 3 | BUSY | МИ ещё читает EEPROM по последнему «Измерению» |
| 2 | EMPTY | на последнее «Измерение» непрочитанных значений не было |
| 1 | VALID | D содержит значение, прочитанное по последнему «Измерению» |
| 0 | RUN | таймер МИ запущен |

VALID и EMPTY сбрасываются, BUSY устанавливается при приёме нового `0xA2`.

### 6.4. Почему «Измерение» — это две транзакции

Чтение из EEPROM по I2C на 100 кГц занимает около 0.5 мс, а между байтами SPI всего 8 мкс, поэтому ответ не успевает попасть в ту же транзакцию. Порядок на МО:

1. Транзакция `A2 00 00 00` (ответ МИ в ней — старый, МО его не использует).
2. Пауза **T_RESP = 2 мс**.
3. Транзакция `00 00 00 00`, проверка: CHK верна, MARK = 1, BUSY = 0.
   - VALID = 1 → D идёт на ЦФ;
   - EMPTY = 1 → отсчёта нет, ничего не пишется;
   - BUSY = 1 → повтор NOP через 1 мс, не более 3 раз, затем ошибка.
4. После `A1` и `A3` МО через 1 мс читает NOP и проверяет RUN (1 и 0 соответственно); при несовпадении повторяет команду до 3 раз.

## 7. Таймеры

Все периоды — параметры модулей (в симуляции уменьшаются).

| Таймер | Период | Что делает | Запуск / остановка |
|---|---|---|---|
| МИ | 1000 мс | чтение ДТ → запись в EEPROM | `A1` / `A3` от МО |
| МО1 | 500 мс | «Измерение» в МИ → ЦФ → Flash | `0x01` / `0x02` от МУ |
| МО2 | 2000 мс | чтение пачки из Flash → UART в МУ | `0x01` / `0x02` от МУ |

- МО1 опрашивает вдвое чаще, чем МИ пишет: очередь в EEPROM не растёт, ответы EMPTY МО просто пропускает.
- Пачка = все записи, накопленные во Flash с прошлого чтения, но **не более BATCH_MAX = 16**. За 2 с набирается около 2 записей, 16 — запас. Передача 16 пакетов по 8 байт ≈ 11 мс.
- Записи, не отправленные до «Стоп», теряются (по «Старт» указатели сбрасываются).
- LM75A сам измеряет примерно раз в 100 мс, опрос раз в 1 с ему подходит.

## 8. Карты памяти

### 8.1. EEPROM МИ (AT24C08, 1024 байта)

| Адрес | Содержимое |
|---|---|
| 0x000..0x3FF | кольцевой буфер: 512 записей по 2 байта (температура Q8.8, старший байт по чётному адресу) |

- Запись № n лежит по адресу 2n. Адрес 10 бит: биты [9:8] идут в адрес устройства (блок P1 P0), биты [7:0] — в байт адреса.
- Запись 2 байт по чётному адресу никогда не пересекает границу страницы (16 байт). После записи — ожидание конца цикла опросом ACK (до 5 мс).
- Указатели `wr_ptr`, `rd_ptr` (9 бит) хранятся в регистрах МИ и обнуляются по `A1`. Если запись догоняет непрочитанное, `rd_ptr` сдвигается вперёд (теряется самое старое) и ставится OVF.
- Ресурс: при 1 записи в секунду каждая ячейка перезаписывается раз в 512 с, 1 млн циклов хватит примерно на 16 лет непрерывной работы.

### 8.2. «Flash» МО (SDRAM, слова по 16 бит)

Линейный адрес слова 23 бита: {bank[1:0], row[11:0], col[8:0]} (используем только 12 строковых линий A0..A11, как разведено на плате).

| Слова | Содержимое |
|---|---|
| 0x00000..0x3FFFF | кольцевой буфер: 65536 записей по 4 слова |
| остальное | не используется (тест памяти на этапе 7) |

Запись № n по адресу 4n:

| Смещение | Слово |
|---|---|
| +0 | MEAS, Q8.8 |
| +1 | FILT, Q8.8 |
| +2 | ERR, Q8.8 |
| +3 | SEQ — порядковый номер записи после «Старт» (только для отладки, в МУ не передаётся) |

- Указатели записи и чтения (16 бит) в регистрах МО, обнуляются по «Старт», стирание не нужно.
- При переполнении (МУ не читает) отбрасываются самые старые записи. При заданных периодах переполнения не бывает.
