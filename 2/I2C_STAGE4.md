# Этап 4: I2C-мастер на плате B — подключение, прошивка, проверка

Протокол и номера выводов — в `PROTOCOL.md` (разделы 2.3, 3.3). Здесь только то, что нужно для проверки на плате.

## 1. Что подключить

Ничего. ДТ (LM75A) и EEPROM (AT24C08) уже на плате B и сидят на шине I2C: SCL — вывод **99**, SDA — вывод **98**.

- Нужна только плата B с её USB-Blaster и питанием по USB.
- Провода SPI с платой A и USB-TTL на этом этапе не нужны (можно оставить, они не мешают: выводы 1, 2, 3, 7, 10, 11 в этом проекте не используются).
- Если есть осциллограф или логический анализатор — подключите щуп к выводам 99 и 98 гребёнки (они же на плате); не обязательно.

## 3. Кнопки

| Кнопка | Что делает |
|---|---|
| KEY1 | выполнить выбранный сценарий |
| KEY2 | следующий сценарий 0..5 (индикатор показывает «P   N») |
| KEY3 | следующий режим индикатора |
| KEY4 | обнулить счётчики, последние данные и список найденных, погасить led[3] |
| RESET | всё в начальное состояние (сценарий 0, режим «0000») |

## 4. Сценарии

| № | Имя | Что делает на шине | Чего ждём на индикаторе |
|---|---|---|---|
| 0 | SCAN | пробует адреса 0x08..0x77 (запись 0 байт): кто ответил ACK | «F1.48», «F2.50», «F3.51», «F4.52», «F5.53» по очереди раз в секунду (номер.адрес). после RESET или KEY4 `t112 n107` в режимах t и n — при пяти ответивших |
| 1 | DT_TEMP | указатель 0x00 в LM75A, повторный START, чтение 2 байт | «XXXX» = регистр температуры: 0x1960 = 25.375 °C, 0x19E0 = 25.875 °C, при нагреве пальцем значение растёт |
| 2 | DT_TOS | то же, указатель 0x03 (регистр Tos) | «5000» (80 °C — значение после включения) |
| 3 | EE_READ | указатель 0x00 в EEPROM, повторный START, чтение 4 байт | «XXXX» = байты 2 и 3 (с адреса 2 и 3); чистая микросхема — «FFFF» |
| 4 | EE_WRITE | запись байта в ячейку 0xF0, опрос ACK до конца цикла записи (до 5 мс), чтение обратно | «00XX», где XX = 5A + число запусков: первый запуск после RESET «005A», второй «005B» и т. д. |
| 5 | ABSENT | адрес 0x2A, на котором ведомого нет | NACK ожидаем: счётчик n растёт, ошибки нет |

Если в сценариях 1–4 микросхема не ответила на адрес, сценарий прерывается и считается ошибкой (led[3], счётчик E).

## 5. Режимы индикатора (KEY3)

| Вид | Что |
|---|---|
| `XXXX` | два последних принятых байта (последний — две младшие цифры) |
| `A XX` | адрес последней транзакции (hex) |
| `5 XX` | итог последней транзакции (буква S выглядит как 5): бит 7 — чтение; бит 3 arb; бит 2 timeout; бит 1 NACK данных; бит 0 NACK адреса |
| `tNNN` | транзакций закончено |
| `nNNN` | NACK на адрес |
| `ENNN` | ошибок (NACK данных, timeout, arb, неожиданный NACK адреса) |
| `Fi.AA` | найденные ведомые: i — номер, AA — адрес; листается раз в секунду; `F0.00` — никого |
| `P   N` | номер выбранного сценария |

Светодиоды (на плате нумерация обратная: LED1 = led[3], LED4 = led[0]): led[0] — START, led[1] — ACK от ведомого, led[2] — NACK от ведомого (вспышки по 50 мс; при SCAN горят почти постоянно), led[3] — была ошибка (до KEY4).

## 6. Порядок проверки

1. Прошить, нажать RESET. Индикатор «0000», светодиоды погашены.
2. KEY2 один раз (сценарий 1), KEY1: led[0] и led[1] мигнули, индикатор «XXXX» с температурой (KEY3 до режима `XXXX`, если сейчас другой режим).
3. Сценарий 0 (KEY2 пять раз до «P   0»), KEY1: ждём ~20 мс, индикатор сам показывает `F1.xx`. **Запишите, какие адреса нашлись**: они пойдут в `PROTOCOL.md` (раздел 3.3).
4. Сценарии 2, 3, 4, 5 по таблице. Для сценария 4 нажмите KEY1 дважды: значение должно измениться на следующее.
5. RESET и проверка нагрева: сценарий 1 несколько раз, пальцем на LM75A — температура должна расти (каждый шаг 0x0020 = 0.125 °C).

## 7. Если что-то не так

| Симптом | Вероятная причина |
|---|---|
| SCAN: `t112 n112`, F0.00, ошибок нет | на шине никто не отвечает: нет подтяжек SDA/SCL (внутренний weak pull-up ~25 кОм может не хватить), микросхемы не питаются или выводы 98/99 не те. Проверить осциллографом, при необходимости подтяжки 4.7 кОм на 3.3 В |
| SCAN: `n0`, нашлись «все» адреса | SDA прижата к нулю (КЗ, выход другой микросхемы), мастер видит ACK на всё |
| Сценарии 1–4: led[3] горит, `E001` | микросхема не ответила на адрес: другой адрес (смотрите результат SCAN), снова проверьте подтяжки |
| `S 04` (timeout) | что-то держит SCL в нуле дольше 1 мс |
| `S 08` (arb) | на SDA не то, что выставил мастер: шина занята или закорочена |
| DT_TOS не `5000` | у LM75A на плате по умолчанию другие значения (даташит: Tos = 80 °C, Thyst = 75 °C) или это не LM75A: сравните с результатом SCAN |
| EE_WRITE: ошибка в ходе ACK-опроса | цикл записи дольше 100 опросов (≈ 12 мс): микросхема не отвечает после записи |
